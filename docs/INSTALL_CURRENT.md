# Установка, подключение и возврат Android / installation status

Актуально: 2026-11-05. Только Lenovo **TB371FC**, не другие модели с похожим названием.
Последняя проверенная установленная комбинация: R226 v2 payload + recovery selector v3.
Описание и SHA256: [experimental/r226](../experimental/r226/README.md).
Последующие [R227–R241](../experimental/community-handoff/README.md) — исследования,
их нельзя подменять под видом стабильного релиза.

## Что важно до установки

Это исходники исследовательского проекта, не готовая пользовательская прошивка.
Полная установка с чистого checkout ещё не проверена. Скрипты содержат зависимости
от промежуточных сборок и старых путей автора. Если не можете воспроизвести и
проверить каждый этап, **не прошивайте**; запросите помощь в issue.
Не скачивайте чужую личную rootfs/initrd: там могут быть действующие ключи и пароли.

Нужны разблокированный загрузчик (разблокировка стирает Android), platform-tools,
Linux/WSL Ubuntu24.04, LLVM18, make, Python3, dtc, cpio, mkbootimg/avbtool,
своя microSD и резервные копии. Сохраните штатные boot/recovery/vbmeta/dtbo обоих
слотов и данные Android. Наш локальный бэкап карты **не** является бэкапом UFS.
Серийник, слот и размеры проверяйте на своём устройстве — не копируйте авторские.
Не блокируйте загрузчик после прошивки модифицированных образов.

## Последовательность сборки и установки

1. Изучить исторические [ROOTFS](ROOTFS.md), [FIRMWARE](FIRMWARE.md),
   [RECOVERY](RECOVERY.md) и [профиль R226](../experimental/r226/README.md).
   ROOTFS содержит также старые испытания 7.1.8; это не готовая rootfs для 6.12.
2. Собрать согласованные ядро Linux6.12.114, DT, модули и initrd. Не смешивать ABI,
   `.ko` разных сборок и разные DT по похожим именам. R226 использует SD150,
   scoped USB-регуляторы, PS5169/PHY и post-panel перезапуск сенсора.
3. Подготовить **свою** rootfs Arch Linux ARM aarch64 с KDE, firmware и соответствующими
   модулями. p1 exFAT хранит загрузочные файлы; p2 ext4 с меткой `tb371fc-root`
   хранит систему. Разметка стирает карту: сначала проверьте диск и бэкап.
   Нужны файлы и слои, ожидаемые загрузчиком, а не просто пустой раздел с меткой.
4. Получить первый этап из **своего** штатного recovery (ядро Lenovo4.19 + ramdisk),
   создать согласованный payload и SHA256-манифест. R226 selector выбирает только
   точные pinned-хэши и ENABLE, иначе возвращается к сохранённому R201.
   Личный готовый recovery автора не опубликован.
5. SD150 привязан к проверенной карте: другая карта требует отдельной безопасной
   валидации. Не удалять проверку идентификатора ради запуска. Начинать с обычной
   скорости/чтения и согласованного низкоскоростного профиля.
6. Только после офлайн-проверок и подготовки отката записать образ recovery
   в проверенный recovery-раздел и соответствующий vbmeta по инструкции сборки.
   На планшете автора использован слот B; не менять слоты вслепую.
   `Image`, `.dtb`, payload.tar.gz и initramfs **не являются fastboot boot.img**.
7. Первый запуск с ПК/оператором. Подтвердить видимый рабочий стол, касания,
   ошибки MMC, фактическую частоту SD, сеть и зарядку. USB3 требует подходящего
   кабеля/порта и фиксированной ориентации=2; Type-C сам по себе не означает USB3.

Не выдаём этот список за автоматический установщик. Следующая полезная задача
сообщества — воспроизводимая сборка и чистый, лишённый учётных данных пакет установки.

## Подключение и работа

Цепочка: ABL → recovery4.19 → проверенный kexec payload с карты → initramfs6.12 →
rootfs на p2 → systemd/KDE. Обычный Android boot остаётся отдельным путём.

Первый этап предоставляет USB ACM-консоль и SSH `127.0.0.1:2222` через serial-bridge;
это **не доступный с ПК напрямую localhost планшета**. Используются
`tb371fc-serial-ssh-bridge.py`, `serial-step.ps1`, `recover-tb371fc-serial-gate.py`.
COM9 — только номер на ПК автора, на другом ПК надо обнаружить свой порт.
Окно автозагрузки можно удержать через предусмотренный загрузчиком hold-механизм;
не отправляйте команды в занятый другим мостом COM-порт.

В загруженном Linux настроенный владельцем SSH доступен на 2223 по Wi-Fi
`tb371fc.local` или USB `172.31.77.2`. `scripts/connect-tablet.ps1` использует
строгую проверку заранее доверенного host key, отдельный ключ и не повторяет
мутацию при переподключении. Эти настройки нужно **создать самому**, они не
возникают после клонирования репозитория. Сверьте отпечаток через доверенную
консоль; не отключайте StrictHostKeyChecking. Смените все исходные пароли rootfs,
создайте новые SSH host/user keys и свой профиль Wi-Fi. Никогда не публикуйте их.

## Полный возврат обычной загрузки Android

На устройстве автора достаточно исходных recovery_b + signed vbmeta_b:
boot/super/userdata для Linux не заменялись. Для вашего планшета это верно
**только если вы также не меняли другие Android-разделы**.
Сверьте хэши собственных бэкапов и текущий слот/размеры до записи:

```sh
fastboot devices
fastboot -s YOUR_SERIAL getvar current-slot
fastboot -s YOUR_SERIAL getvar partition-size:recovery_b
fastboot -s YOUR_SERIAL getvar partition-size:vbmeta_b
# Только если проверен именно слот B и эти файлы — ваши исходные бэкапы:
fastboot -s YOUR_SERIAL flash recovery_b YOUR_ORIGINAL_recovery_b.bin
# Продолжать только после подтверждённого OKAY предыдущего шага:
fastboot -s YOUR_SERIAL flash vbmeta_b YOUR_ORIGINAL_SIGNED_vbmeta_b.bin
fastboot -s YOUR_SERIAL reboot
```

Порядок важен: сначала исходный recovery, затем подписанный vbmeta. Не включать
проверку поверх оставшегося несовместимого recovery. Не стирать userdata и не
прошивать super, boot, persist или чужие калибровки ради этого отката.
Проверить Android на экране и обычную повторную перезагрузку. Карту форматировать
только после сохранения Linux: форматирование карты без возврата recovery само
по себе не восстанавливает штатный загрузчик.

English summary: this is a source/developer installation guide, not a complete
image release. Start with R226, preserve your own stock partitions, adapt build
paths, provision new credentials and test rollback. R227–R241 are not stable
features. Restore original recovery before signed vbmeta; never erase Android
userdata or flash another tablet's calibration/identity partitions.
