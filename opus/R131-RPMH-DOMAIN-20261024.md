## Confirmed configuration mismatch

Command DB exists at /sys/kernel/debug/cmd-db, valid ARC entries are readable,
and its platform driver is bound to 80860000.memory. Earlier hypothesis of an
absent Command DB is ruled out for current R130.

/soc/rsc@18200000 has power-domains=<0x24>, pointing to the PSCI CPU cluster
genpd. CONFIG_ARM_PSCI_CPUIDLE is NOT SET. CPU cluster genpd is absent from
pm_genpd_summary. platform_probe() attaches a power domain BEFORE calling the
RPMh driver's probe. Missing provider is a strong explanation of the repeated
-EPROBE_DEFER and eventual -ETIMEDOUT. This is source/config evidence, not a
traced return-path proof. No claim that all RPMh/display issues are solved.

R131 removes ONLY that RSC power-domains property. rpmh_rsc_probe() explicitly
supports missing pdev->dev.pm_domain by registering a CPU PM notifier instead.
CPU idle/extra cores remain disabled as before; no new low-power mode enabled.
RPMh registration may expose further inherited-state/power/clock defects, so a
successful USB boot of this new DT must still be verified.
