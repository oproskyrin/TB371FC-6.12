# R148: working touchscreen on the 6.12 KDE desktop

2026-10-24. User confirmed: touches land exactly where pressed in KDE.

## What was used

- Driver: project patch `mainline-port/patches/0002-input-touchscreen-add-nt36523-spi-pen.patch`
  (written for 7.1), built unchanged as an external module for the R130/R140
  kernel: `scripts/build-r148-touch-module.sh` -> `D:/TB371FC-builds/r148-touch/nt36523_ts.ko`,
  SHA256 1de00b7d…, vermagic `6.12.30-tb371fc-r130-usb2-late+ SMP preempt mod_unload modversions aarch64`.
- Firmware already in the Arch rootfs: `lenovo/tb371fc/novatek_ts_tm_fw_6.bin`
  (panel-id gpio82=1 -> Tianma).
- DT (`scripts/prepare-r148-touch.sh`, DTB b1dd3d85…, exact R140 Image/initramfs):
  - `spi@880000` (qup14) and its `touchscreen@0` child: status okay;
  - `interconnects`/`interconnect-names` removed from that SPI node: no ICC
    provider is loaded in R140 and it would defer forever (same approach as
    R130 USB); bootloader QUP bandwidth is kept;
  - TLMM `gpio-reserved-ranges` now also frees gpio40-43 (SPI), 56 (TP reset),
    68 (TP irq), 82 (panel id). All other GPIOs stay reserved.
  Roundtrip back to the R140 DT verified.
- Runner `scripts/test-r121-r148-touch.sh` (all 8 CPUs, as R147).

## Hardware run

Boot 2a2edda0-76ac-4919-a538-f11bd020aeb7. `880000.spi` bound to geni_spi,
`spi14.0` present. `insmod /run/nt36523_ts.ko` (`scripts/r148-touch-load.sh`):
trim 20 00 00 32 65 03, firmware update success in 189 ms, fw_ver 0x1A, PID 6068,
inputs NVTCapacitiveTouchScreen + NVTCapacitivePen, IRQ 170. udev tags
ID_INPUT_TOUCHSCREEN. 1701 events in a 25 s raw capture.

## Calibration

The digitizer is portrait-native (X 0..18400, Y 0..29440 with super-resolution 10),
the desktop is landscape. Two measured corners (`scripts/r148-touch-corner.sh`):
top-left X≈17399 Y≈650, top-right X≈17722 Y≈28784. So screen u = Y, v = 1 - X:
`LIBINPUT_CALIBRATION_MATRIX=0 1 0 -1 0 1`, applied by a udev rule for touch and
pen (`scripts/r148-touch-calibrate.sh`), then module reload. Confirmed by the user.
