# R174–R175: запись на microSD из 6.12, переразметка карты, постоянный корень (2026-10-25)

## Запись на microSD (R174)
- Причина отказа записи: 4.19 работает с картой в SDR104 (линии 1.8 В, pm8150a L6) и уходит в
  6.12 через kexec без выключения — шина остаётся на 1.8 В, а 6.12 держит площадки SDHC2 в
  режиме 3.0 В (CORE_VENDOR_SPEC=0xA9C). Чтение работало, запись давала CRC-ошибки и
  «card removed». Мост BayHub BH201 тут ни при чём (ggc_chip_init ничего не пишет в чип).
- Исправление: модуль `scripts/r174-bh201/tb371fc-bh201.c` ставит IO_PAD_PWR_SWITCH_EN|1V8
  (0x20C bits 15/16) и повторяет после каждого сброса контроллера. 300/300 циклов 16 КиБ без
  ошибок, файлы 16/64 МБ сверены. Таймаут 0xE (как у Lenovo) не нужен.
- Одна аварийная перезагрузка при записи 256 МБ (причина не найдена) испортила тестовую
  папку exFAT (каталог и файл на одном кластере) — исправлено fsck.exfat (статический
  exfatprogs 1.2.6), образы ext4 проверены e2fsck — целы.
- Буферизованная запись на блочное устройство ~1 МБ/с (мелкие запросы в PIO), прямая
  (O_DIRECT, 4 МБ) — 5.4 МБ/с.

## Переразметка (пользователь разрешил форматировать карту — на ней только служебные папки Android)
- Резервная копия на ПК: D:/TB371FC-builds/sd-backup-20261025 (e2image образа, слои, payload).
- Раздел 1: exFAT 20 ГиБ (LBA 2048–41945087): образ консоли 4.19 (уменьшен до 8 ГиБ,
  sha 99a78b56), слои r163/r171, файлы автозагрузки. Консоль 4.19 не менялась.
- Раздел 2: ext4 `tb371fc-root` 99.3 ГиБ (LBA 41945088–конец): образ + оба слоя, слитые
  (root.img sha 33b8ab7d), растянут resize2fs.
- Сервисный режим (Linux 6.12 только в RAM): cmdline `tb371fc.maint`, USB 172.31.77.2:2323,
  статические mkfs.exfat/fsck.exfat/e2fsck/resize2fs/tune2fs/mke2fs в /usr/maint,
  автоперезагрузка через 15 мин без связи. Инструмент ПК: scripts/tb371fc-ncm.py.
  Первые две попытки были без связи (ранний USB в initramfs отключён; start-usb.sh требует
  ярлыки busybox) — оба раза нужна была ручная перезагрузка.

## R175
- initramfs: если есть mmcblk0p2 с меткой tb371fc-root — модуль 1.8 В, e2fsck -p, монтирование
  rw как корень (без слоёв и RAM-оверлея); иначе старый путь (образ + слои + RAM).
- Рабочий стол: русский/раскладки/125 % один раз (метка /var/lib/tb371fc/desktop-defaults-v1).
- Хеши: initramfs 841ebcb0, recovery 8defe90b (PASS), откат R173 c1be9671.
- Проверено: корень /dev/mmcblk0p2 rw (98 ГБ, 91 свободно), KDE, Wi-Fi, Bluetooth; файл
  пережил перезагрузку, ext4 clean.

## Дальше: скорость карты
- DT: max-frequency 25 МГц → 50 МГц (High Speed допускает 50), DMA (iommus + без
  sdhci-caps-mask) — варианты в D:/TB371FC-builds/r176-sd-speed (prepare-r176-sd-speed-dt.sh).
- SDR104: нужна подстройка BH201; образец — патчи BayHub sdhci-bayhub для SDM845/SC7180
  (не приняты в mainline).

## R178: UHS SDR50 (2026-10-25)
- Предел карты (4.19, SDR104 + подстройка BH201): чтение 92.4 МБ/с.
- В 6.12 UHS при старте контроллера (DT без no-1-8-v) вешает загрузку ещё до /init (асинхронный
  probe sdhci-msm). Переключение после старта работает: модуль `scripts/r178-uhs/tb371fc-uhs.c`
  (снимает NO_1_8_V, включает режимы UHS, mmc_hw_reset) — карта ещё в 1.8 В от 4.19, ядро
  выбирает UHS через v18 fixup без CMD11.
- SDR104 (202 МГц): чтение верно, запись — Data CRC, таймауты, «card removed» (нужна выходная
  подстройка моста BH201 sela/selb из кода Lenovo). SDR50 (100 МГц): чтение и запись чисто.
- R178: initramfs переводит карту в SDR50 перед монтированием корня (`tb371fc.nouhs` отключает,
  `tb371fc.uhs=N` задаёт режимы); при неудаче загрузчик поднимает USB-оболочку 172.31.77.2:2323.
- Итог: чтение **46.5 МБ/с**, запись **32.3 МБ/с** (утром 6.3/5.1), стресс 8×256 МБ чисто.
- R178: Image 55fcf49e, DTB 635df17d, initramfs 291258e8, recovery e3d34d1d (PASS), откат R177.
