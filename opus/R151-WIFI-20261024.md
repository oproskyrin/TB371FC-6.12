# R151: Wi-Fi (QCA6390, ath11k over PCIe0) on the 6.12 desktop

2026-10-24. Result: wlp1s0 connected to the user's network on 5 GHz,
Wi-Fi 6 (wifi_generation=6), WPA2-PSK CCMP, DHCP 192.168.1.156/24, internet and
DNS work, and SSH over Wi-Fi works from the PC (`ssh -p2222 root@<wlan ip>`).
Everything is in RAM; nothing is persistent yet.

## Kernel side

Kernel = R140 Image (6.12.30-tb371fc-r130-usb2-late+), unchanged. Modules built for
it by `scripts/build-r151-wifi-modules.sh` (copy of the r130 build dir; in-tree
modules in ONE make call so modpost resolves cross-module symbols; QMP PCIe PHY as
an external module because PHY_QCOM_QMP is not configured), plus crypto/michael_mic.ko
(ath11k needs it for the rx defrag context, `-2` without it):
cfg80211, mac80211, ath, qmi_helpers, ath11k, ath11k_pci, pwrseq-core,
pwrseq-qcom-wcn, pci-pwrctrl-core, pci-pwrctrl-pwrseq, phy-qcom-qmp-pcie, michael_mic.
Output `D:/TB371FC-builds/r151-wifi/modules/` (+SHA256SUMS, vermagic verified).

## DT (`scripts/prepare-r151-wifi-dt.sh`, DTB 1e615168…, base = R148 DTB)

Modelled on qrb5165-rb5.dts:
- `pcie@1c00000` and `phy@1c06000` okay (PHY/host rails inherited -> dummy regulators);
- `/qca6390-pmu`: external *-supply removed (no RPMh regulator driver in this kernel,
  rails stay on from the boot chain); WLAN_EN gpio20 / BT_EN gpio21 kept;
- new `pcie@0/wifi@0` `pci17cb,1101` with the nine PMU LDO supplies (pwrctrl device);
- TLMM: additionally free gpio20, 21, 79, 80, 81. Everything else stays reserved.

## Bring-up (boot 52edf8c3-45e2-4bc2-b833-49a12e356bc8)

Payload R151 = R140 Image + R149b initramfs + R151 DTB (`scripts/package-r151-wifi.sh`,
runner `scripts/test-r121-r151-wifi.sh`; the R150 autoboot was cancelled by touch).
`scripts/r151-wifi-load.sh` loads the modules (PHY last). Results:
- qca6390-pmu bound to pwrseq-qcom_wcn; PHY probed; "Phy link never came up" on the
  first try, then the pwrctrl device powered the chip and the rescan found
  `01:00.0 [17cb:1101] QCA6390` -> ath11k_pci "qca6390 hw2.0";
- ~60 s stall: the optional `ath11k/QCA6390/hw2.0/firmware-2.bin` is absent and the
  kernel uses the sysfs fallback (60 s timeout); then MHI powered on, firmware
  WLAN.HST.1.0.1.r1-01596, interface wlp1s0;
- wpa_supplicant (RAM config with hashed PSK in /run) + dhcpcd (systemd-networkd
  ignored a 0600 .network file) -> connected; second sshd bound to the wlan IP.
Unrelated, pre-existing: PMIC SPMI warnings and "spurious spmi irq apid=77".

## Not done

- Not persistent: modules, DT, Wi-Fi credentials and sshd live in RAM. Making it
  automatic needs a new payload (DTB + initramfs with the modules and a service)
  and, for power-on autoboot, a new recovery with new pinned hashes (R150 pins R149b).
- The Wi-Fi password is not stored in the repository or logs.
- Bluetooth (same chip, UART) not attempted. Long-run stability not tested.
- The firmware-2.bin 60 s stall can be avoided by loading modules after userspace
  or by disabling the fallback (firmware_class.fallback ... or placing the file).
