# R166–R168: причина зависаний (RAM после kexec), NetworkManager, попытка записи на SD, 2026-10-25

Итог: recovery_b = **R167** (56212fab…), автозагрузка `tb371fc-linux/autoboot-6.12-r167`.
Зависания под нагрузкой на память устранены; Wi-Fi через NetworkManager (выбор сетей в KDE);
троттлинг с 75 °C; блокировка экрана выключена. Запись на microSD из 6.12 по-прежнему не работает
(нужна поддержка моста BayHub BH201). Откат: R165 61e5638d → R164 → R163 → R158.

## Причина зависаний: недоступная RAM в карте памяти после kexec

- memtester 4G вешал систему за ~20 с (RCU stall, ядро 7 без ответа на NMI); то же на ядре 0
  (`taskset`), то же с `mem=5G` (не верхний hotplug-блок); cpuidle в ядре отсутствует —
  не режимы сна. Нагрузка 8 ядер без памяти — без зависаний.
- Модуль `tb371fc-memscan.ko` (только чтение, по слову со страницы, `scripts/r166-memscan/`):
  полный скан остановился между 0x1d0000000 и 0x1d1000000; скан с шагом 1 МиБ — между
  0x1d0c00000 и 0x1d0d00000, на двух загрузках одинаково.
- В 4.19 (`/proc/kpageflags`) 0x1d0000000–0x1d33fffff — сплошная полоса составных выделений по
  1 МиБ без флагов (буферы драйверов 4.19, вероятно отданные защищённому миру); блок памяти mem14
  для 4.19 — обычная online-RAM, в его reserved-memory этого нет. Карта памяти 6.12 при kexec
  строится из «System RAM» 4.19, поэтому 6.12 считает этот участок свободным.
- Исправление: DT R166 d427da0e = R165 + `reserved-memory` no-map 0x1d0000000/64 МиБ
  (`scripts/prepare-r166-memhole-dt.sh`). Полный скан 7,1 ГБ проходит, memtester 4G — все тесты ok.
- Регионы PIL/DSP в mainline DT совпадают с kona.dtsi адрес в адрес.

## R167 (прошит)

initramfs 4b0c5d85 (`scripts/r163-config`): Wi-Fi через NetworkManager (`r166-nm.sh`, профиль
домашней сети из PSK-хеша, PMF выключен глобально — ath11k с PMF даёт CONN_FAILED, USB-интерфейс
unmanaged), `r166-thermal-tune.sh` (26 пассивных порогов cpu/gpu → 75 °C), Autolock/LockOnResume
false. Проверено после прошивки: дыра reserved, слой apps, NM connected, звук, cpufreq-hw.
Найдено: timesyncd не синхронизирует время, если сеть появилась позже (NM) — в `r166-nm.sh`
добавлен перезапуск timesyncd (войдёт в следующую сборку).

## Запись на SD (R166/R168t, не решено)

- Загрузчик R129 ставит `blockdev --setro`; для теста снималось.
- R166 (broken-cd): «mmc0: card 59b4 removed» в первую секунду записи → корень потерян.
- R168t DT 99d1cb23 (non-removable): карта не «выпадает», но первая запись — «tried to HW reset
  card, got error -110», «recovery failed», I/O errors; чтение работает.
- В Lenovo 4.19 карта за мостом BayHub BH201 (`drivers/mmc/host/sdhci-bh201.c`; в sdhci-msm:
  `sdhci_bht_set_timeout` (0xE), `sdhci_bht_execute_tuning`, патчи power on/off). В 6.12 нет.
- На карте остался недописанный тестовый файл `tb371fc-linux/sdtest/test.bin`, exFAT «dirty»
  (плюс прежние ~25 ГБ утерянных кластеров) — нужна чистка из 4.19 / fsck.exfat.
