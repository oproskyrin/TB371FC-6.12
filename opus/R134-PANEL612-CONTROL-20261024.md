## Implementation

Copied original R118 donor to isolated /root/tb371fc/linux-6.12-r134-panel,
fresh output /root/tb371fc/build-6.12-r134-panel. Imported validated panel source
from /root/tb371fc-linux-7.1.7-longwrite-repro into versioned project backports.
Preserved Tianma/BOE command tables, reset, dual PPS, populated-DSC guard,
forced LP long vendor packets and canonical sleep/display commands.

Linux6.12 adaptation replaces devm_drm_panel_alloc with devm_kzalloc plus
drm_panel_init, and provides the two missing dual-device context macros using
6.12's existing multi-context error accumulation. First compile detected the
second missing macro mipi_dsi_dual; corrected and final Image/modules built.
No runtime symbol/version bypass used.

Panel bridge: moved propagation of prepare_prev_first into the common
drm_panel_bridge_add_typed constructor, matching the newer implementation.
6.12 already sets it in two wrapper constructors, but not the common one;
this closes a path-dependent ordering gap rather than claiming all6.12
panel bridge users previously ignored the flag.

Ported existing dual-KTZ8866 source as an external module, default brightness
128/2047 instead of1200. It remains unloaded in the control package.

Configuration based on exact R130: BACKLIGHT_CLASS_DEVICE=y;
DRM_PANEL_NOVATEK_NT36523=m; SM_DISPCC_8250=m; INTERCONNECT_QCOM=m,
SM8250=m and selected BCM_VOTER/RPMH=m; LOCALVERSION=r134-panel.
Numerous newly visible Kconfig entries remain unset. See config.diff.
USB QCOM and FEMTO PHY remain late modules, rebuilt for this new kernel.
Nine modules total: twoUSB, DISPCC, fourICC, panel, dualbacklight.
