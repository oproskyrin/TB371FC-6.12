## Changes and rationale

Fresh output directory; original R118 donor sources unchanged. Configuration
changes: local version r130-usb2-late, GENERIC_PHY=y, USB_DWC3_QCOM=m,
PHY_QCOM_USB_SNPS_FEMTO_V2=m. Previous configuration had Generic PHY disabled.
Both modules have the exact new kernel vermagic and CONFIG_MODVERSIONS support.
External module build required modules_prepare to generate scripts/module.lds;
resumed build and source integrity checks passed.

DT starts from exact R129: GPIO75-only reservation and SD redriver high retained.
USB wrapper enabled; USB2 peripheral/high-speed only; USB3 PHY disabled.
USB2 reference clock uses inherited fixed 19.2MHz clock. PHY regulator phandles
removed to use dummy fallback with rails inherited from first-stage USB.
Wrapper interconnect dependencies removed; GCC power domain/clocks/resets and
DWC3 IOMMU mapping retained. This is a diagnostic power-management assumption,
not a completed regulator/ICC port. Multiple changes mean results cannot isolate
one factor. Source review suggests repeated child creation on ICC probe deferral
could explain old repeated IOMMU-group messages; this is not proven on hardware.

R129 root loader remains byte-identical under /bin/boot-arch-r129-base.
Nine direct-read checks, RO exFAT/loop/ext4 and tmpfs OverlayFS remain.
No early USB setup. After Arch evidence timer, runtime services load PHY then
Qualcomm USB modules and configure ACM + NCM. Modules live only under /run;
not installed into /lib/modules, so no planned early udev autoload.

USB NCM: tablet 172.31.77.2/30, host DHCP lease 172.31.77.1, no gateway/DNS.
Dedicated SSH port 2222, public-key-only root login. Only public development
key included, never private key. ACM exposes serial-getty as a second path.
Logs: /run/r130/{steps.txt,dmesg.txt,deferred.txt,udc.txt,network.txt,udhcpd.log}
and journal units r130-usb/r130-sshd. All changes are volatile.

Userspace timeouts bound ordinary module-loading failures, but cannot guarantee
recovery from a kernel hang, panic or uninterruptible task. PMIC/SPMI IRQ defect
is not fixed; USB activation may still expose hardware faults.
